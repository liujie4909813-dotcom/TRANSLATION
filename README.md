# zh2en · 中文输入即时转英文

在任意软件里打中文，变成英文。两种形态：**翻译台窗口**（不依赖任何快捷键，最稳）和 **全局快捷键**（更快，但取决于系统能否收到按键）。

## 先用这个：翻译台（不需要快捷键）

双击 **`翻译台.bat`** → 屏幕右下角出现一个小窗口。

1. 点一下窗口里的输入框
2. 用你平时的输入法打中文，**停一下就自动出英文**（也可以按 Enter）
3. 想贴回刚才那个窗口：`Ctrl+Enter`
4. `Esc` 只清空输入，不进翻译；右上角 × 退出工具

这条路完全不碰键盘钩子，只要窗口能打开就一定能用。快捷键那套按不动时，用这个。

## 快捷键用法（可选）

**1. 选中就替换**

在微信/浏览器/Word/IDE 里打好中文 → 选中 → `Alt+[` → 选中的中文原地变成英文。

```
这个版本我先发测试环境，明天再上正式环境。   ← 选中这段，按 Alt+[
I'll release this version to the test environment first, and then deploy to production tomorrow.
```

**2. 弹窗输入（写在哪儿都行）**

什么都不选，直接按 `Alt+[` → 弹出一个输入框 → 用你自己的输入法打中文 → `Enter` 出英文。

- `Enter` 翻译
- `Ctrl+Enter` 翻译 + 直接把英文贴回你刚才那个窗口（光标位置）
- `Esc` 关掉

这条其实最接近「输入法直接出英文」：你正常打中文，英文自动落到聊天框里。

**3. 英文看中文（反向）**

选中一段英文 → `Alt+;` → 弹出一个小窗，里面是中文译文。**不会改动你选中的原文**，只是给你看。

```
Ship this version to staging first, then production tomorrow.   ← 选中这段，按 Alt+;
→ 先将此版本发布到暂存环境，然后明天发布到生产环境。
```

弹窗里：`复制译文` 一键拿走，`Esc` 关掉。原文一个字都不动，适合读英文文档、看报错、翻别人的 commit message。

**4. 剪贴板翻译**

复制一段中文 → `Alt+]` → 剪贴板里的内容变成英文，直接 Ctrl+V 用。

## 快捷键

| 快捷键 | 作用 |
| --- | --- |
| `Alt+[` | 选中中文→英文替换；没选中→弹输入框 |
| `Alt+;` | 选中英文→弹窗显示中文（不改原文） |
| `Alt+]` | 剪贴板中文→英文 |
| `Ctrl+Alt+Shift+Q` | 退出（原来的 `Ctrl+Alt+Q` 在有些机器上被别的软件占用，所以换成加 Shift） |

按键在 `config.json` 里改，改完重启生效。写法就是 `alt+[`、`alt+;`、`ctrl+alt+t` 这种。反向热键对应配置项 `hotkey_translate_reverse`。

**注册方式**：走 Windows 的 `RegisterHotKey`（系统级热键），不是低级键盘钩子。好处有两个——注册成不成功启动时就告诉你，不会出现「按了完全没反应」的黑盒；而且按下的键被系统直接吃掉，不会漏一个 `[` 到你正在打字的框里。

启动窗口里会列出注册结果：

```
  已注册热键（系统级 RegisterHotKey）:
      alt+[
      alt+;
      alt+]
      ctrl+alt+shift+q
```

有一条写「[失败] … 已被别的程序占用」，就改 `config.json` 换键位。

**不会漏字**：`Alt+[` 被系统当成热键消费掉，不会在你正在打字的框里留下一个 `[`；单独打 `[` `]` 也完全正常。

## 启动

- **`翻译台.bat`** —— 常驻小窗口，不用快捷键（**推荐，最不容易出问题**）
- **`启动翻译.bat`** —— 全局快捷键模式，带黑窗口看日志
- **`后台静默启动.vbs`** —— 全局快捷键模式，无窗口（退出按 `Ctrl+Alt+Q`）

启动后窗口里会显示：

```
  >> 已就绪。选中中文按 ALT+[ 转英文，
             选中英文按 ALT+; 看中文。
  已注册热键（系统级 RegisterHotKey）:
      alt+[ / alt+; / alt+] / ctrl+alt+shift+q
```

每次按键动作都会在窗口里打一行日志（取到几个字、用的哪个引擎、有没有替换成功），出问题不用猜：

```
[12:47:05] 命中 alt+[
[12:47:06] 取到 22 字（复制）：'这个版本先发测试环境，明天上正式环境。'
[12:47:08] 译文(mymemory 1932ms)：'This version goes to test environment first...'
[12:47:08] 已替换 ✓
```

**按不动就先跑 `自检.bat`**（环境/依赖/弹窗/剪贴板/翻译/热键六项逐个验）。
**快捷键没反应但自检全绿，就跑 `按键诊断.bat`**，按两下 `Alt+[`，屏幕会打印系统实际收到的键名和状态，把那段发我就能定位。

依赖（keyboard、pyperclip）已经装到系统 Python 3.12 上了，换电脑才需要跑一次 **`安装依赖.bat`**。

## 踩过的坑（重要）

**启动脚本必须优先用 `py` 启动器，不能用 `python`。**
这台机器上 `python` 第一个命中的是 WorkBuddy 自带的 Python 3.13，它**没有 tkinter**，弹窗会直接失效。`py` 指向 `C:\Windows\py.exe`，自动选中装有 tkinter 的 3.12。

**批处理文件必须用 CRLF 换行 + 纯 ASCII 内容。**
LF 换行会让 `cmd.exe` 解析 `goto` 标签失败，双击后窗口一闪就关（这就是之前「闪退」的原因）。现在三个 bat 都是 CRLF、零非 ASCII 字节，中文提示全部交给 Python 打印。改 bat 的时候别用会写成 LF 的编辑器。

## 实现细节 / 你可能会问

- **翻译引擎**：MyMemory 免费接口，无需 Key、国内直连。实测 Google 在你这台机器上超时，有道/微软返回 403，所以配了自动降级链：`mymemory → google → youdao`，第一个失败自动换下一个。
- **不会删你的原文**：回写前会校验剪贴板真的写进去了，校验不过就不发 Ctrl+V（否则剪贴板是空的会把选中内容直接删掉）。真失败了原文保持不动，译文会显示在右下角提示里。
- **复制被吞时自动退回剪切**：有些程序（终端、部分游戏、Electron 应用）会吃掉 Ctrl+C，这时改用 Ctrl+X 取走原文；万一后面翻译失败，会把原文原样贴回去。
- **速度**：单次 1.5~2.5 秒，相同句子命中内存缓存后是 0 秒。
- **额度**：MyMemory 匿名每天约 5000 词，日常聊天完全够。爆了的话在 `config.json` 的 `providers` 里加自己的接口。
- **没动你的剪贴板**：替换走「写入→粘贴→还原」，原剪贴板内容会恢复（`restore_clipboard: true`）。
- **粘贴方式** `insert_method`：默认 `auto`（先注入 Ctrl+V，检测到没落地再补 WM_PASTE）；也可以强制成 `paste`（只注入）、`message`（只发消息，某些环境下更稳）、`type`（逐字敲入，最慢最兼容）。
- **不含中文的文本会跳过**，不会把英文再翻一遍。

## 常见问题

**按了没反应？**
目标程序如果是管理员权限运行的（比如某些游戏、管理员终端），Windows 会拦住低权限的按键模拟。右键 `启动翻译.bat` → 以管理员身份运行。

**快捷键被别的软件占了？**
改 `config.json`，比如换成 `ctrl+alt+z`。`alt+[` 在某些编辑器/浏览器里可能有别的用途，撞上了就换。

**按了真的一点动静都没有（启动窗口里连「命中 alt+[」都没打印）？**
先看启动窗口里有没有 `已注册热键` 这一段。没有的话，说明注册失败了，上面会写明原因（多数是 `已被别的程序占用`，换个键位就行）。跑 `自检.bat` 的第 6 项也能直接看到每个组合键能不能注册。

**有「命中 alt+[」，但没替换成功？**
看紧跟着的几行日志，它会把每步都说清楚：

```
[13:03:39] 命中 alt+[            ← 热键通了
[13:03:39] 取到 21 字（Ctrl+C）  ← 选中内容拿到了
[13:03:41] 译文(mymemory 1914ms) ← 翻译成了
[13:03:41] 已替换 ✓              ← 写回去了
```

- 卡在「没取到选中内容」：确认你真的框选了字；`WM_COPY 也没拿到` 说明那个程序不吃消息（游戏、部分自绘界面的软件），只能改用翻译台
- 卡在「译文」没出来：网络或接口问题
- 有译文但「回写失败」：剪贴板被别的程序占着，重按一次

抓取选中内容有三条路自动降级：注入 `Ctrl+C` → 给控件发 `WM_COPY` → 注入 `Ctrl+X`。回写也自动降级：注入 `Ctrl+V` → 补发 `WM_PASTE`（只在检测到控件里还是中文时才补，不会重复粘贴）。所以就算安全软件把按键注入拦了，记事本 / Word 这类标准控件照样能用。

**在终端里按了变成中断当前命令？**
终端里 Ctrl+C 是 SIGINT。选中文本再按（有选中时终端会复制），或直接用弹窗模式。

**弹窗没出来？**
说明启动用的 Python 缺 tkinter。用 `启动翻译.bat`（优先走 `py` 启动器 / 系统 Python），别用 WorkBuddy 自带的那个 Python。

**想让它更准 / 控制语气（正式、口语、技术文档）？**
免费接口做不到。要接 DeepSeek / GPT 这类大模型，改 `zh2en.py` 里的 `translate()`，加一个 provider 函数塞进 `PROVIDERS` 就行，其它逻辑不用动。

**为什么不直接做个输入法？**
真正的 Windows 输入法要注册 TSF/IME 组件、做候选词窗、处理各种宿主程序兼容，还得签名，工程量是这套的几十倍。现在的方案在体验上已经覆盖 95% 的场景，成本却低得多。

## 文件

```
zh2en/
├── zh2en.py           主程序（纯标准库 + keyboard/pyperclip）
├── config.json        快捷键、引擎顺序、粘贴方式
├── 翻译台.bat          常驻翻译窗口，不用快捷键（推荐）
├── 启动翻译.bat        全局快捷键模式，带窗口
├── 自检.bat           六项环境自检，出问题先跑这个
├── 按键诊断.bat        打印系统实际收到的按键，快捷键不灵时跑
├── 后台静默启动.vbs     全局快捷键模式，无窗口
├── 安装依赖.bat        换机器时装依赖
└── README.md
```

命令行：

```bash
py zh2en.py --tr "这个需求下周能上线吗"   # 只测翻译（中→英）
py zh2en.py --zh "Ship it tomorrow"       # 只测翻译（英→中）
py zh2en.py --check                       # 六项自检
py zh2en.py --keys                        # 按键诊断，40 秒
```
